# Приоритизация и состав MVP

## 1. Цель

Определить порядок историй по методу WSJF, рассчитать ёмкость на MVP и выбрать состав MVP как задачу о рюкзаке с зависимостями. Сравнить точное решение с жадным по WSJF и объяснить расхождения.

## 2. Исходные данные

- Размеры историй в story points: [estimates.md](estimates.md), данные `data/estimates.csv`.
- Зависимости историй: [backlog.md](backlog.md), раздел 4.
- Предварительная линия MVP: [story-map.md](story-map.md).
- Оценки для WSJF: `data/wsjf.csv`. Из них скрипт `scripts/wsjf.py` формирует `data/release_backlog.csv` в формате `release_planner.py`.
- Допущения для расчёта ёмкости (условные):
  - фактическая дата защиты ЛР 3 не определена, срок принят условно: **3 недели**;
  - доступное время: **22 часа в неделю** (около трёх часов в день);
  - коэффициент фокуса: **0,7**;
  - пересчёт: **1 SP ≈ 2 часа** (см. estimates.md).
  Значения будут заменены реальными данными по результатам ЛР 4.

## 3. Ход выполнения

### 3.1. WSJF

**WSJF** (Weighted Shortest Job First) показывает, сколько пользы приносит история на единицу затраченной работы:

```
WSJF = (V + T + R) / размер
```

- **V** (ценность для пользователя): насколько история важна для автора и респондента;
- **T** (срочность): насколько она блокирует другие истории или нужна к срокам этапов;
- **R** (снижение риска): насколько она снимает неопределённость;
- **размер**: story points из estimates.md.

V, T, R оцениваются по шкале Фибоначчи (1, 2, 3, 5, 8, 13), сумма V + T + R называется стоимостью задержки (CoD).

### 3.2. Ёмкость команды на MVP

```
W (часы) = недели × часы в неделю × коэффициент фокуса
         = 3 × 22 × 0,7 = 46,2 ч

W (SP)   = W (часы) / (часов на 1 SP) = 46,2 / 2 = 23,1  →  23 SP
```

Пояснения:

- **Коэффициент фокуса 0,7** означает, что 30% времени уходит не на разработку: другие предметы, переключения, разбор ошибок, самопроверка.
- **Пересчёт в story points:** 1 SP ≈ 2 часа (оценка из estimates.md, раздел 3.4: ожидаемые 43,50 ч по пяти историям весом 21 SP дают 2,07 ч/SP).
- **Округление вниз** до 23, чтобы не планировать неполную историю.

Для сравнения: весь бэклог 30 SP (≈ 60 ч), то есть в ёмкость он целиком не помещается, и выбор состава MVP необходим.

### 3.3. Выбор MVP как задача о рюкзаке

**Переменные:** x_i ∈ {0, 1}: история i входит в MVP (1) или нет (0).

**Целевая функция:** максимизировать суммарную ценность выбранных историй

```
max  Σ v_i · x_i,     где v_i = V_i + T_i + R_i  (CoD из таблицы 3.1)
```

**Ограничение ёмкости:** суммарный размер не больше W

```
Σ w_i · x_i ≤ 23,     где w_i размер истории в SP
```

**Зависимости** (история j входит только вместе с той, от которой зависит; в формулах: x_j ≤ x_i):

```
x02 ≤ x01
x03 ≤ x02, x03 ≤ x07
x04 ≤ x02, x04 ≤ x07
x05 ≤ x02
x06 ≤ x05
x07 ≤ x05
x08 ≤ x07
x09 ≤ x08, x09 ≤ x03
x10 ≤ x07
```

**Обязательные истории:** x01 = x02 = x05 = x07 = 1. Это сквозной путь «создать опрос → добавить вопрос → опубликовать → ответить»; без него продукт не работает (15 SP, суммарная ценность 97).

Таким образом, на выбор остаётся 23 − 15 = **8 SP** среди историй US-03, 04, 06, 08, 09, 10.

### 3.4. Решение и сравнение с жадным алгоритмом

Решение получено `release_planner.py` (точный метод ветвей и границ и жадное решение по убыванию v/w):

```
python scripts/release_planner.py docs/01-planning/data/release_backlog.csv --capacity 23
```

| Решение | Состав | Ценность | SP | Историй |
|---------|--------|----------|----|---------|
| **Оптимальное** (ветви и границы) | US-01, 02, 05, 07, 08, 10 | **139** | 23 | **6** |
| Жадное по WSJF | US-01, 02, 03, 04, 05, 06, 07, 08 | 132 | 23 | 8 |

Оптимум лучше жадного на 7 единиц ценности (5,3%).

**Почему решения расходятся.** Жадный алгоритм идёт по убыванию WSJF и берёт всё, что помещается. После обязательных историй он берёт US-08 (WSJF 6,33; занято 18 SP), затем US-06 (WSJF 5,00; занято 19 SP). До экспорта US-10 (WSJF 4,60) очередь доходит, когда свободно лишь 4 SP, а нужно 5, поэтому US-10 не помещается. Оставшиеся 4 SP он тратит на US-03 и US-04, и эти три истории вместе с US-06 (всего 5 SP) дают 5 + 6 + 5 = 16 единиц ценности. А экспорт на те же 5 SP даёт 23. Это классический недостаток жадной стратегии: она не видит, что пропуск крупной ценной истории обходится дороже, чем набор мелких.

Второе замечание: жадный состав содержит 8 историй, а в MVP для одного исполнителя допустимо 4–6. Оптимальный состав из 6 историй этому требованию соответствует.

**Чувствительность к ёмкости.** Если реальная ёмкость окажется 20 SP, а не 23, состав меняется: вместо экспорта US-10 в MVP войдёт шкала US-03 (оптимум 122, жадное 121). Это показывает главный риск плана: экспорт помещается в MVP только при ёмкости не менее 23 SP, поэтому US-10 имеет смысл делать последней среди историй MVP.

### 3.6. Как воспроизвести

```
python scripts/wsjf.py
python scripts/release_planner.py docs/01-planning/data/release_backlog.csv --capacity 23
```

Первая команда пересчитывает WSJF и обновляет `release_backlog.csv`, вторая решает задачу о рюкзаке (если запускать другую ёмкость, меняйте значение `--capacity`).

## 4. Выводы

- Рассчитан WSJF для всех историй; в лидерах US-05, US-02 и US-08, то есть истории с высокой ценностью при малом размере.
- Ёмкость на MVP составляет 46,2 ч, или 23 SP, при условных допущениях (3 недели, 22 ч в неделю, фокус 0,7, 2 ч на SP).
- Задача о рюкзаке с зависимостями и обязательными историями решена точно: MVP из 6 историй, 23 SP, ценность 139.
- Жадное решение по WSJF уступило оптимальному на 5,3% и вышло за лимит в 6 историй, потому что мелкими историями «съело» место для экспорта.
- Состав MVP чувствителен к ёмкости: при 20 SP экспорт из MVP выпадает.
- Следующий шаг: сетевой график, критический путь, PERT и прогноз Монте-Карло (задание 1.5).
